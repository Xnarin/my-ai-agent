## Layered Architecture 흐름

클라이언트의 요청은 Router → Service → Repository 순서로 처리된다. 처리 결과는 Repository → Service → Router를 거쳐 HTTP 응답으로 전달된다.

---

### Router: 요청과 응답

클라이언트가 `POST /posts-layered`로 제목과 내용을 보내면 `routers/post_router.py`가 요청을 받는다. `PostCreate`로 받은 데이터를 Service에 전달하고, 결과를 응답 모델에 맞춰 `201`로 반환한다.

```python
@router.post("", response_model=PostDetailResponse, status_code=status.HTTP_201_CREATED)
def create_post(data: PostCreate):
    return post_service.create_post(data)
```

### Service: 규칙 확인과 작업 진행

`services/post_service.py`의 `PostService`는 빈 제목과 내용을 거절한다. 검증을 통과하면 게시글 객체를 만들고 Repository에 저장을 요청한다.

```python
def create_post(self, data: PostCreate):
    if data.title == "":
        raise HTTPException(
            status_code=status.HTTP_422_UNPROCESSABLE_CONTENT,
            detail="title을 입력하세요",
        )

    if data.content == "":
        raise HTTPException(
            status_code=status.HTTP_422_UNPROCESSABLE_CONTENT,
            detail="content를 입력하세요",
        )

    new_post = Post(title=data.title, content=data.content)

    return post_repository.save(new_post)
```

Service가 예외를 발생시키면 저장을 요청하지 않고 작업을 중단한다. FastAPI가 해당 예외를 `422` 오류 응답으로 전달한다.

### Repository: 데이터 저장

`repositories/post_repository.py`의 `PostRepository`는 게시글에 ID를 부여하고 메모리의 리스트에 저장한다.

```python
def save(self, new_post: Post):
    self.post_id += 1
    new_post.id = self.post_id
    self.posts.append(new_post)
    return new_post
```

저장한 게시글 객체는 Service와 Router를 거쳐 클라이언트에 반환된다. 저장소의 구현은 Repository가 담당하고, 저장 전에 무엇을 확인할지는 Service가 담당한다.
