# 가상 금융 업무 에이전트 (mini-project-3)

은행 앱의 계좌 조회, 이체, 카드 분실 정지를 자연어 요청으로 처리하는 LangGraph 에이전트입니다. 데이터를 바꾸는 업무는 LangGraph의 중단·재개(`interrupt` / `Command`)로 사용자 승인을 받은 뒤에만 실행합니다.

- LLM(Gemini)은 요청을 해석하는 데만 씁니다. 검사와 데이터 변경은 Python 함수가, 승인은 그래프의 중단 단계가 맡습니다.
- 설계 자료: [설계 초안](docs/design_draft.md), [최종 설계와 변경 내용](docs/design_final.md), [회고](docs/retrospective.md)

## 실행 방법

1. [uv](https://docs.astral.sh/uv/)를 설치하고, `.env` 파일에 Gemini API 키를 넣습니다.
   ```dotenv
   GEMINI_API_KEY=발급받은_API_키
   ```
   `load_dotenv()`는 실행 파일 위치에서 상위 폴더로 올라가며 `.env`를 찾습니다. 이 저장소에서는 `my-ai-agent/.env`를 그대로 씁니다.
2. `mini-project-3` 폴더에서 패키지를 설치합니다.
   ```bash
   uv sync
   ```
3. 에이전트를 실행합니다.
   ```bash
   uv run src/main.py
   ```
   요청을 입력하고, 승인 질문에는 `승인` 또는 `거절`을 입력합니다. 종료하려면 `/exit`를 입력합니다.
4. 작업용 데이터를 처음 상태로 되돌리려면 아래 명령을 실행합니다. 원본(`data/initial_data.json`)을 작업용 복사본(`data/data.json`)으로 다시 복사합니다.
   ```bash
   uv run src/data_store.py
   ```

- 사용자는 `user-001`로 고정되어 있습니다.
- 실행하면 `Direct use of automatic function calling ...` 경고가 한 번 나올 수 있습니다. 라이브러리가 띄우는 안내 문구라 동작에는 영향이 없습니다.
- 작업용 복사본 `data/data.json`은 실행할 때마다 바뀌어서 git에 올리지 않습니다. 파일이 없으면 실행할 때 원본에서 자동으로 만듭니다.

## 구현한 기능

| 기능 | 내용 |
|---|---|
| 계좌 조회 | 본인 계좌별 잔액을 보여줍니다. |
| 즉시이체 | 본인 계좌끼리 이체합니다. 검사 → 승인 → 실행 순서로 처리하고, 두 계좌의 잔액과 거래 내역 2건을 한 번에 저장합니다. |
| 카드 조회 | 본인 카드의 이름·ID·종류(신용·체크)·상태를 보여줍니다. |
| 카드 분실 정지 | 사용 가능하거나 일시 잠금된 카드를 승인 후 분실 정지합니다. 잔액과 거래 내역은 바꾸지 않습니다. |
| 처리 결과 확인 | "아까 이체가 됐어?"처럼 물으면 저장된 처리 기록을 근거로 완료·거절·실패 여부와 내용을 안내합니다. |
| 승인·거절 | 변경할 내용을 보여주고 그래프를 멈춘 뒤, `승인`/`거절` 입력으로 이어서 실행합니다. 다른 답을 입력하면 다시 묻습니다. |
| 변경 결과 저장·조회 | 승인한 변경은 JSON에 저장되고, 이후 조회에 저장된 값이 나옵니다. |
| 불완전하거나 실행할 수 없는 요청 안내 | 금액 오류, 잔액 부족, 없는 계좌·카드 같은 불가 이유를 안내하고, 처리할 수 없는 요청은 할 수 있는 업무를 안내합니다. |
| 추가 질문 | 빠진 정보(출금 계좌, 입금 계좌, 금액, 카드)를 하나씩 후보와 함께 되묻고, 답하면 앞 요청과 합쳐서 처리합니다. |
| 처리 기록 | 변경 요청마다 결과(완료·거절·실패)를 `requests`에 남깁니다. |

### B. 추가 질문과 실패 상황

```text
요청: 이체해줘.
답변: 어느 계좌에서 보낼까요? (생활비, 저축, 여행 자금)

요청: 생활비
답변: 어느 계좌로 보낼까요? (저축, 여행 자금)

요청: 저축
답변: 얼마를 보낼까요?

요청: 5만 원
다음 이체를 승인하시겠습니까?
  생활비 → 저축 50,000원
승인 / 거절: 응
'승인' 또는 '거절'을 입력하세요: 거절

요청: 아까 이체는 어떻게 됐어?
답변: 생활비 계좌에서 저축 계좌로 5만 원을 이체하려던 요청은 사용자가 취소하여 **거절**되었습니다.

답변: '비상금' 계좌를 찾을 수 없습니다. (생활비, 저축, 여행 자금 중에서 골라 주세요)

요청: 여행 카드 잃어버렸어. 정지해줘.
다음 카드를 분실 정지하시겠습니까?
  여행 카드
승인 / 거절: 승인
답변: 여행 카드 (card-002) 분실 정지 완료

요청: 여행 카드 정지해줘.
답변: 여행 카드는 이미 분실 정지되어 있습니다.

요청: 회사 카드 정지해줘.
답변: '회사 카드'에 해당하는 카드가 없습니다. (생활비 카드, 여행 카드 중에서 골라 주세요)

요청: 오늘 날씨 어때?
답변: 지금은 계좌·카드 조회, 이체, 카드 분실 정지, 처리 결과 확인만 할 수 있어요.
```

### 직접 선정한 실패 상황

| 상황 | 요청 | 결과 | 데이터 |
|---|---|---|---|
| 정보 부족 | 이체해줘. | 출금 계좌 → 입금 계좌 → 금액을 차례로 되묻고, 답하면 이어서 승인 요청 | 변경 없음 |
| 승인 입력 오류 | 승인 질문에 "응" | '승인' 또는 '거절'을 다시 물음 | 변경 없음 |
| 사용자 거절 | 승인 질문에 "거절" | 요청 취소 안내, 처리 기록에 거절로 남음 | 변경 없음 |
| 금액 0 이하 | -1만 원 이체 | 승인 요청 없이 금액 오류 안내 | 변경 없음 |
| 잔액 부족 | 1억 원 이체 | 승인 요청 없이 현재 잔액과 함께 안내 | 변경 없음 |
| 같은 계좌 | 생활비 → 생활비 | 승인 요청 없이 안내 | 변경 없음 |
| 없는 계좌 | 비상금 → 저축 | 본인 계좌 후보와 함께 안내 | 변경 없음 |
| 이미 정지된 카드 | 여행 카드 정지 (두 번째) | 승인 요청 없이 이미 정지됐다고 안내 | 변경 없음 |
| 없는 카드 | 회사 카드 정지 | 본인 카드 후보와 함께 안내 | 변경 없음 |
| 처리할 수 없는 요청 | 오늘 날씨 어때? | 할 수 있는 업무 안내 | 변경 없음 |

### 자체 점검

각 파일 아래의 `__main__` 블록에서 assert로 동작을 확인합니다. 시작과 끝에 작업용 데이터를 초기화합니다.

```bash
uv run src/functions.py
```

```bash
uv run src/graph.py
```

- `functions.py`: 이체 불가 조건 8개, 정상 이체 뒤 두 계좌 잔액과 거래 내역 2건, 이름이 같은 다른 사용자 계좌·카드는 그대로인지, 카드 분실 정지 검사 3개, 처리 기록 저장을 확인합니다.
- `graph.py`: Gemini를 호출해서 추가 질문 → 답 반영 → 승인, 거절, 금액 오류, 카드 분실 정지, 이미 정지된 카드, 처리 결과 확인까지 실행합니다. 승인한 10만 원만 잔액에 반영되고 처리 기록이 `실패·완료·거절·실패·완료·실패` 순서로 남는지 확인합니다.
