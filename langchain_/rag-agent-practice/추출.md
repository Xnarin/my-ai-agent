# PDF 추출 정리

59개 PDF, 1,258쪽을 콘텐츠 종류(글 / 표 / 이미지 / 그래프 / 다이어그램)별로 다른 방법으로 추출했다.
결과는 페이지 단위 JSONL(`output/extracted/jsonl/`)과 미리보기 md(`output/extracted/INDEX.md`)로 저장.

## 한눈에 보기

| 종류 | 사용한 라이브러리 / 모델 | 결과 형태 | 개수 |
|---|---|---|---|
| 글 (텍스트) | **pdfplumber** | 줄 단위 텍스트 | 869쪽 텍스트형 + 207쪽 혼합형 |
| 표 (PDF 글자) | **pdfplumber** `find_tables()` | 마크다운 표 + 각주 | 147개 |
| 가짜 표 (1행/1열) | pdfplumber → 일반 텍스트 처리 | 텍스트 | 299개 |
| 이미지 속 글자 | **RapidOCR** (PP-OCRv5 한국어) | 줄 단위 텍스트 | 462곳 |
| 이미지 속 표 | **rapid-layout** (PP-DocLayoutV3) + **rapid-table** (SLANet+) | 마크다운 표 | 56개 |
| 그래프·차트 | rapid-layout으로 찾기 → **Gemini** (gemini-3.6-flash) | 값 표 + 요약 | 277개 |
| 다이어그램·도형 | rapid-layout으로 찾기 → **Gemini** | `→` 관계 + 들여쓰기 목록 + 요약 | 152개 |
| 이미지 표 중 구조 인식 실패 | **Gemini** | 마크다운 표 | 15개 |
| OCR 실패 이미지 | **Gemini** | 종류별 마크다운 (사진은 한 줄 설명) | 53곳 |

### RapidAI 도구 묶음 (쉽게 설명)

**RapidAI**는 GitHub의 오픈소스 그룹 이름이다. 이 그룹이 문서 처리 도구를 **각각 따로** 만들어 두었고,
이번에는 그중 3개를 골라 조합해서 썼다. (하나의 OCR 라이브러리 안에 있는 함수가 아니라 별도 패키지)

```
RapidAI (GitHub 그룹)
 ├─ rapidocr      글자 읽기 (OCR)                 ← "이 글자는 '퇴직연금'이다"
 ├─ rapid-layout  페이지 구역 나누기 (글은 안 읽음) ← "여기는 표, 여기는 차트, 여기는 본문"
 └─ rapid-table   표의 행·열 구조 복원             ← "이 글자는 2행 3열 칸에 들어간다"
```

| 패키지 | 하는 일 | 안에 든 모델 | 설치 |
|---|---|---|---|
| rapidocr | 글자를 찾아서 읽기 | PP-OCRv5 한국어 | `pip install rapidocr` |
| rapid-layout | 페이지에서 어디가 무엇인지 구역 분류 | PP-DocLayoutV3 | `pip install rapid-layout` |
| rapid-table | 표 이미지 → 행·열 구조(HTML) | SLANet+ | `pip install rapid-table` |

- 원래 바이두의 **PaddleOCR 모델**을 무거운 Paddle 없이 **onnxruntime으로 가볍게** 돌리게 만든 것 → GPU 없이 CPU로 실행 가능
- 모델 파일은 처음 실행할 때 자동으로 내려받음
- 한 그룹이라 서로 잘 맞물림: rapid-table은 rapidocr의 OCR 결과를 그대로 받아서 셀에 배치

이번 작업에서 셋을 이렇게 연결했다:

```
rapid-layout  →  구역 찾기
   ├─ 표 구역     → rapidocr로 셀 글자 읽기 → rapid-table로 행·열 배치 → 마크다운 표
   ├─ 차트 구역   → Gemini
   └─ 이미지 구역 → 글자 상자가 많으면 다이어그램 → Gemini / 적으면 사진이라 제외
```

### 처리 순서

```
extract.py      PDF → 글·표 추출, 이미지 위치 표시         (pdfplumber)
ocr_images.py   이미지 → OCR, 이미지 속 표 → 마크다운 표     (RapidOCR, rapid-layout, rapid-table)
find_figures.py 전체 페이지 → 그래프·다이어그램 찾기         (rapid-layout)
vision_gemini.py 그래프·다이어그램·실패 영역 → 마크다운       (Gemini)
```

## 1. 글 (텍스트)

- **라이브러리:** `pdfplumber` 0.11
- **여백 제거:** 위 6%, 아래 7%, 좌우 3%를 잘라냄 (`within_bbox`, 경계에 걸친 글자도 버림)
  - 실제 PDF들의 쪽번호가 높이 93.8~96.6% 지점에 있어서 아래쪽만 7%
  - 결과: 쪽번호·머리말·꼬리말 제거 (남은 쪽번호 1곳 - 안과감염병 지침, 본문 쪽에 있음)
- **중복 글자 제거:** `dedupe_chars()` (굵은 글씨를 겹쳐 찍은 PDF)
- **2단 편집:** 가운데 30~70% 구간에서 단어가 가장 적게 걸치는 세로선을 찾아 좌/우 단 분리
  - 제목처럼 두 단에 걸친 줄은 전체 폭 구간으로 따로 읽음
  - 172쪽이 2단 (주로 의학 논문)
- **깨진 글자:** 폰트에 매핑이 없어 `(cid:123)`으로 나오는 글자 24,587개 제거
  - 깨진 비율 30% 넘는 페이지(46쪽, 주로 증시콘서트 자료집)는 페이지 전체를 이미지로 처리

## 2. 표 (PDF 글자로 된 표)

- **라이브러리:** `pdfplumber` `find_tables()` (34번 노트북 방식)
- **변환:** 빈 행·빈 열 제거 → 첫 행을 헤더로 → 마크다운 표
  - 병합된 첫 열 빈칸은 직전 값으로 채움
  - 표 바로 아래에 이어지는 각주(`*`, `※`, `주:`, `자료:`, `출처:`)를 표에 붙임
- **가짜 표 규칙:** **1행 또는 1열(1행 1열 포함)은 표가 아니라 일반 텍스트**로 처리 (안내 박스 등) → 299개
- **결과:** 표 147개
- **한계:** 의학 논문(enm, KJFP)의 선 없는 표는 한 행씩 따로 잡혀 텍스트로 들어감

## 3. 이미지 (글자가 있는 이미지·스캔본)

- **대상 선정 (pdfplumber):**
  - 페이지 면적 10% 넘는 이미지
  - 글자가 없는 페이지 중 아래 경우는 페이지 전체를 이미지로 처리

    | 경우 | 쪽 수 | 예 |
    |---|---|---|
    | 글자를 벡터 곡선으로 그림 (이미지도 글자도 아님) | 53 | luxury 보고서 전체 |
    | 폰트 깨짐 `(cid)` | 46 | 증시콘서트 자료집 |
    | 슬라이드가 작은 이미지 조각으로 나뉨 | 25 | 한-호주 퇴직연금 책자 |

- **OCR:** `rapidocr` 3.10 + **PP-OCRv5 한국어 인식 모델** (CPU, onnxruntime)
  - 렌더링 200dpi
  - 기본 모델(PP-OCRv6)은 한국어 미지원이라 v5 사용
  - **방향 분류기 끔** (`use_cls=False`): 문단 첫 줄을 180도 뒤집어 "위연업위터극량터"처럼 깨뜨림 → 끄고 나서 핵심 문장 인식 0/7 → 6/7
  - 신뢰도 0.5 미만 글상자는 버림
  - 이미 PDF 글자로 읽힌 영역과 겹치는 글상자는 버림 (배경 이미지 위 텍스트 중복 방지)
  - 2단 감지를 OCR 글상자에도 적용해 읽기 순서 정렬
- **결과:** 515곳 중 462곳 OCR 완료 (평균 신뢰도 대부분 0.95 이상)
  - 글자를 못 찾았거나 평균 신뢰도 0.8 미만인 53곳 → Gemini로 넘김 (5번)
- **이미지 PNG:** `output/extracted/images/`

## 4. 이미지 속 표

- **표 영역 찾기:** `rapid-layout` + **PP-DocLayoutV3** (레이아웃 분석, 표 신뢰도 0.5 이상)
- **표 구조 인식:** `rapid-table` + **SLANet+** → HTML → 마크다운 표 (rowspan/colspan 병합 셀은 값 반복)
  - 셀 글자는 3번과 같은 PP-OCRv5 한국어 OCR 결과를 사용
- **걸러내기:** 1행/1열 표는 텍스트로, 데이터 칸이 절반 넘게 비면(구조 인식 실패) 기존 OCR 텍스트로 둠
- **결과:** 표 56개 (OCR 텍스트 안 원래 위치에 마크다운 표로 삽입)
  - 숫자 위주의 반듯한 표는 원본과 거의 같음 (예: 한-호주 p.21, p.27 / 증시콘서트 p.6)
  - 글자가 많거나 서식형 표는 셀이 비거나 섞임 (예: 중국 라이브커머스 p.8) → 깨진 것은 Gemini로 다시 처리 (5번)

## 5. 그래프·다이어그램 (Gemini)

### 대상 찾기 — `find_figures.py`

- 모든 페이지(여백 제거)를 150dpi로 렌더링해 **PP-DocLayoutV3**로 영역 분류
  - 렌더링한 화면 기준이라 **PDF에 선으로 그린 벡터 차트도 잡힘** (이미지가 아니라서 이전 단계에서는 누락됐던 것)
- 분류 기준

  | 레이아웃 결과 | 처리 |
  |---|---|
  | chart | 그래프로 대상 |
  | image + 글자 상자 4개 이상 | 다이어그램으로 대상 (글자 상자 수는 RapidOCR 검출만 사용) |
  | image + 글자 거의 없음 | 사진·로고·장식 → 제외 |
  | 이미지 속 table 중 구조 인식 실패·빈 열 있음 | 표로 대상 |
  | 페이지 면적 2% 미만 | 아이콘 → 제외 |

- 결과: 497개 = 그래프 277 + 다이어그램 152 + 깨진 표 15 + OCR 실패 53

### 변환 — `vision_gemini.py`

- **모델:** `gemini-3.6-flash` (`langchain-google-genai`, API 키는 `.env`의 `GOOGLE_API_KEY`)
- **종류별 프롬프트** (공통: 글자는 그대로 옮기고 요약·생략 금지, 없는 내용 추측 금지, 못 읽으면 `[확인 불가]`)

  | 종류 | 결과 형식 |
  |---|---|
  | 그래프 | `### [차트] 제목` + 단위·축·범례 + **값을 마크다운 표로** (어림한 값은 `(추정)`) + `요약:` |
  | 다이어그램 | `### [다이어그램] 제목` + 박스 글자 전부 + 관계는 `A → B`, 계층은 들여쓰기 목록 + `요약:` |
  | 표 | `### [표] 제목` + 마크다운 표 (병합 셀 값 반복, 각주 보존) |
  | OCR 실패 | 종류를 먼저 판단 → 위 형식대로 / 사진·로고는 `[이미지] 한 줄 설명` |

- **결과:** 497개 전부 변환 (실패 0, 14분, 입력 약 66만 / 출력 약 92만 토큰)
  - OCR 실패 53곳 중 34곳은 빈 이미지·사진으로 판정
  - 91개 블록에 `[확인 불가]` 포함
- **저장:** 그래프·다이어그램·표는 페이지에 `figure` 블록으로 추가, OCR 실패는 기존 이미지 블록 텍스트를 교체
- **검수 필요:** 글자를 가끔 잘못 읽음 (예: "수탁자이사회" → "수탁사이사회"), 그래프 값은 대부분 `(추정)`
- **알아 둘 점:** 벡터 차트의 축 숫자·라벨은 PDF 글자로 본문에도 흩어져 있어 Gemini 결과와 일부 겹침

## 남은 한계 (개선점)

- 의학 논문의 선 없는 표 → 표 구조 없이 텍스트로 들어감
- 옆에 있는 강조 문구 박스가 본문 줄 사이에 끼어 들어가는 읽기 순서 문제 (luxury p.17 등)
- Gemini 결과의 글자 오인식·추정 값 → 골든셋에 쓰는 그림은 원본과 대조 필요
- 벡터 차트 라벨이 본문 텍스트와 Gemini 결과에 중복

## 그 외 사용할 수 있는 라이브러리 (대안)

이번에는 안 썼지만 같은 일을 할 수 있는 것들. 개선 실험이나 비교할 때 참고.

### 글 (PDF 텍스트 추출)

| 라이브러리 | 특징 | 이번에 안 쓴 이유 |
|---|---|---|
| PyMuPDF (`fitz`) | 매우 빠름, 블록·좌표 정보 풍부, 페이지 렌더링도 가능 | pdfplumber로 충분 (표 찾기까지 한 번에 됨). 라이선스 AGPL 주의 |
| pymupdf4llm | PDF → LLM용 마크다운 바로 변환 | 표·여백 처리를 직접 제어하기 어려움 |
| pypdf | 설치 가볍고 단순 | 좌표·레이아웃 정보가 약함 (LangChain `PyPDFLoader`가 이것) |
| pdfminer.six | 저수준 텍스트·좌표 추출 | pdfplumber가 이걸 감싼 것 |

### 표

| 라이브러리 | 특징 | 이번에 안 쓴 이유 |
|---|---|---|
| Camelot | PDF 표 전용, 선 있는 표(lattice)·선 없는 표(stream) 모드 | 추가 설치(Ghostscript 등) 필요. 선 없는 논문 표 개선용으로 시도해 볼 만함 |
| tabula-py | PDF 표 추출 | Java 필요 |
| img2table | 이미지 속 표를 OpenCV로 찾고 OCR과 연결 | rapid-table로 대체 |
| Table Transformer (Microsoft) | 표 찾기·구조 인식 딥러닝 모델 | torch 필요, CPU에서 느림 |

### OCR (이미지 글자)

| 라이브러리 | 특징 | 이번에 안 쓴 이유 |
|---|---|---|
| Tesseract (`pytesseract`) | 가장 유명한 오픈소스 OCR, 한국어 데이터 있음 | 프로그램 별도 설치 필요, 한국어 품질은 PaddleOCR 계열보다 낮은 편 |
| EasyOCR | 설치 쉬움, 한국어 지원 | torch 필요, CPU에서 느림 |
| PaddleOCR | rapidocr 모델의 원본 | Paddle 프레임워크가 무거움 → rapidocr가 경량 버전 |
| Surya | 다국어 OCR + 레이아웃 분석 | torch 필요, GPU 권장 |
| 네이버 CLOVA OCR / Google Cloud Vision | 유료 API, 한국어 품질 좋음 | 비용 |

### 레이아웃 (구역 나누기)

| 라이브러리 | 특징 | 이번에 안 쓴 이유 |
|---|---|---|
| PaddleOCR PP-Structure | 레이아웃 + 표 + OCR 통합 | 무거움 → rapid-layout/rapid-table이 같은 모델의 경량 버전 |

### 그래프·다이어그램

| 방법 | 특징 | 이번에 안 쓴 이유 |
|---|---|---|
| DePlot / MatCha (Google) | 차트 이미지 → 표 전용 모델 | 영어 위주라 한국어 라벨 약함, CPU에서 느림 |
| PP-Chart2Table (PaddleOCR) | 차트 → 표 | 중국어·영어 중심, 한국어 품질 미확인 |
| OpenCV 도형·선 검출 + OCR | 박스별 글자 묶기, 화살표 연결 추정 | 단순한 그림만 되고 쉽게 깨짐 |
| 로컬 VLM (Qwen2.5-VL 등) | 무료로 Gemini처럼 마크다운 변환 | GPU 필요 (GT 710으로는 불가, CPU는 장당 몇 분) |
| 다른 LLM (GPT-4o, Claude 등) | Gemini와 같은 방식 | 비용·성능 비교용으로 바꿔 끼울 수 있음 |

### 올인원 (PDF → 마크다운 한 번에)

| 도구 | 특징 | 참고 |
|---|---|---|
| Docling (IBM) | 레이아웃·표·OCR → 마크다운 | torch 필요, 무거움 |
| Marker | PDF → 마크다운, 품질 좋음 | GPU 권장 |
| MinerU | 논문·보고서 → 마크다운 | 설치·모델이 무거움 |
| Unstructured | `partition_pdf`로 요소별 분리, LangChain 연동 | hi_res 모드는 무거움 |
| Upstage Document Parse | 한국 회사, 한국어 문서에 강함 | 유료 API |
| LlamaParse / Azure Document Intelligence | 클라우드 문서 파싱 | 유료 API |

> 올인원 도구는 편하지만 내부 처리를 제어하기 어렵다. 이번에는 **1행 1열 규칙, 여백 제거처럼 직접 정한 기준을 적용**하려고 단계별로 나눠서 직접 조합했다.
