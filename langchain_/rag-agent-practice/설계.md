# 정리 (이야기 해보고 결정한 것)

※ 구조 ※

* 슈퍼바이저 X -> 기능이 검색 하나뿐이라 굳이 나눌 필요 없음
* 단일 에이전트로 간다 -> 분야는 메타데이터(domain)로만 남겨두기
* 검색은 툴로, 흐름(최대 3회 재검색)은 LangGraph 노드로

`검색 -> 근거 판단 -> 충분하면 답변(파일명, 페이지) / 부족하면 검색어 바꿔서 재검색 -> 3번 해도 없으면 보류`

* 슈퍼바이저는 나중에 기능 늘어나면(계산, 웹검색 등) 그때 추가 실험으로



※ 추출 ※ -> 34번 노트북 방식 그대로

* 텍스트 -> pdfplumber
* 표 -> find_tables() -> 마크다운 표 + 각주
* 이미지 -> 면적 10% 넘는 것만 Gemini로 마크다운 변환
* 스캔본(글자 없는 PDF 6개)은 페이지 전체가 이미지라 10% 규칙에 자동으로 걸림

`추가할 것`

* 59개 파일 자동으로 돌리기 -> 가짜 표(1행, 안내 박스) 거르기
* 결과는 JSONL로 저장 -> 한 페이지씩 저장해서 중간에 끊겨도 이어서 가능
* 추출은 한번만, 청킹 실험은 저장된 JSONL 불러서

`주의`

* 선으로 그린 차트(벡터)는 이미지로 안 잡힘 -> 실패하면 개선점으로 쓰기
* golden_set.csv는 DB에 넣지 말기 -> *.pdf만 읽기



※ 청킹 ※

* 기본 300 / 겹침 50 -> 페이지 평균 890자라 3조각 정도, 정답 대부분 200자 이하
* 표는 행 단위로 자르고 헤더 반복 (노트북 방식)
* 비교 : 300/50 vs 800/100
* 벡터DB는 설정별로 따로 저장



※ 검색기 ※ -> 09번 노트북 참고

* 기본 : Similarity 검색 (Chroma + Google 임베딩) -> 청킹 실험할 때 이걸로 고정
* 비교 : Similarity vs BM25(Kiwi) vs Hybrid(RRF)
* Hybrid 유력 -> 개념 질문은 Similarity, 숫자/사건번호/고유명사는 BM25가 잘 찾음
* MMR은 탐색형 질문용이라 뺌 (넣으면 비교군으로만)
* 나중에 개선 : Re-ranking, domain 필터

`순서 : Similarity로 시작 -> 청킹 정하기 -> 검색기 비교 -> 이긴 걸로 에이전트 연결`



※ 테스트 순서 ※

1. 청킹, 임베딩 끝나면 -> 내가 만든 골든셋으로 먼저 테스트 (개수 적어서 빠르게 확인)
2. 그 다음 golden_set.csv 268개로 테스트 (숫자 많아서 비교 결과 믿을만함)
3. 그 후 심화 테스트 -> 검색기 비교, Re-ranking, 에이전트(재검색) 등



※ 골든 셋 수정할 것 ※

* csv 형식 맞추기 + 근거 구절 컬럼 추가
* 페이지는 PDF 물리 페이지 1부터로 통일
* 질문은 맞다/틀리다 판단 되게 구체적으로
* 분야별 4~6개 -> 총 20~30개, 문단/표/이미지 섞기
* 문서에 없는 질문 3~5개 넣기 -> 보류 되는지 확인용
* luxury 17p 질문은 스캔본이라 텍스트 추출로는 안 나옴 -> Gemini 처리 확인용으로 좋음
