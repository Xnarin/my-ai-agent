### 멀티 에이전트 종합 실습 — 힌트

아래 패턴은 구현 예시이며 필수 조건이 아닙니다. 각 역할을 단일 에이전트나 별도의 LangGraph 워크플로로 구현할 수 있습니다.

### 에이전트별 패턴 예시

| 에이전트 | 적용할 수 있는 패턴 | 흐름 예시 |
| --- | --- | --- |
| 조사 | Orchestrator-Worker, Parallelization, Tool Agent | 조사 항목 생성 → 항목별 조사 → 결과 종합 |
| 기획 | Plan-and-Execute, Prompt Chaining, Tool Agent | 계획 수립 → 단계별 작성 → 결과 종합 |
| 검토 | Reflection, Evaluator-Optimizer | 초안 평가 → 피드백 반영 → 완료 여부 판단 |

음식점 창업 예시에서 조사 에이전트는 고객·업종·메뉴를 나누어 분석할 수 있습니다. 기획 에이전트는 메뉴·가격·운영·홍보 계획을 단계별로 작성할 수 있고, 검토 에이전트는 예산과 인력 조건에 맞는지 확인하여 계획을 개선할 수 있습니다.

반복하는 패턴을 사용한다면 최대 반복 횟수를 정해 두는 것이 좋습니다.

### 파일 구조 예시

```text
src/
├── main.py
├── graph.py
└── agents/
    ├── __init__.py
    ├── planning.py
    ├── review.py
    └── research/
        ├── __init__.py
        ├── prompts.py
        ├── nodes.py
        └── graph.py
```

간단한 에이전트는 `planning.py`, `review.py`처럼 한 파일로 시작할 수 있습니다. 에이전트의 상태, 노드와 프롬프트가 많아지면 `research/`처럼 역할별 패키지로 분리할 수 있습니다.

| 파일 | 역할 |
| --- | --- |
| `prompts.py` | 에이전트가 사용하는 프롬프트 |
| `nodes.py` | 그래프의 State, 구조화된 출력 모델과 노드 함수 |
| `graph.py` | 노드와 엣지를 연결하고 그래프를 컴파일 |

실제 검색이나 데이터 조회 도구가 필요해지면 `tools.py`를 추가할 수 있습니다. 조사 그래프를 상위 그래프에서 호출할 Tool로 감싸는 코드는 최상위 `src/graph.py`에 둘 수 있습니다.

### 에이전트 조합 힌트

에이전트를 선택하고 실행하는 방법도 자유롭게 정할 수 있습니다.

| 방식 | 구성 예시 |
| --- | --- |
| Router | 요청을 분류하여 실행할 에이전트를 선택한다. |
| 조건부 엣지 | 분류 결과에 따라 각 에이전트 노드로 연결한다. |
| Supervisor | 에이전트를 Tool로 제공하고 필요한 역할을 선택하게 한다. |

단일 기능 요청에는 해당 에이전트만 실행하고, 복합 요청에는 필요한 에이전트를 여러 개 선택할 수 있습니다.

대화 기록은 최상위 `graph.py`에서 Checkpointer로 관리해도 됩니다. 모든 하위 에이전트가 각각 전체 대화 기록을 관리할 필요는 없습니다. `main.py`의 반복문에서 같은 `thread_id`를 사용하면 같은 실행 세션의 대화를 이어갈 수 있습니다.
