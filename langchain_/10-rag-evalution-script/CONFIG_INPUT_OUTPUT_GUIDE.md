# RAG 실험 스크립트 가이드

## 목표

RAG evaluation 과정을 여러 실험 조건으로 테스트하고 비교할 수 있는 스크립트를 작성한다.

- ex) rerank 도입 전/후 비교, 청크 사이즈 변경 후 테스트 등
- RAG 성능을 올리기 위해 어떤 input들을 변경시키면서 테스트할지 정한다.
- 성능 향상과 trade-off 관계에 있는 비용, 시간, 리소스 등도 함께 살펴본다.

> 429 에러가 다시 나는 경우, 10번 자료의 "exhausted 해결 부분"을 참고해서 재시도/백오프 설정을 추가하고, 재시도 횟수를 넉넉히 늘려서 진행한다. 시간이 조금 더 걸릴 수 있다.

## RAG 실험 프로그램에 input으로 넣으면 좋은 것

코드를 수정하지 않고 실험 조건을 바꿀 수 있도록, 아래 항목들을 config(또는 CLI 인자)로 분리한다. 실행할 때 사용한 값을 결과와 함께 저장하면 어떤 조건이 검색 및 생성 품질에 영향을 주었는지 비교하고, 같은 실험을 다시 재현할 수 있다.

모든 항목을 반드시 입력으로 받을 필요는 없으며, 비교하려는 조건과 실행마다 달라질 수 있는 값을 중심으로 선택한다.

| 항목 | 용도 |
|---|---|
| 문서 경로 | 검색에 사용할 PDF 선택 |
| 평가 데이터 경로 | 질문, 기준 답변, 정답 문서나 페이지가 있는 golden set 선택 |
| `chunk_size` | 문서를 나눌 청크 크기 설정 |
| `chunk_overlap` | 인접 청크가 겹치는 범위 설정 |
| 임베딩 모델 | 문서와 질문을 벡터로 변환할 모델 선택 |
| 검색 전략 | Similarity, MMR, BM25, Hybrid 중 활용할 방식 선택 |
| `k` | 가져올 검색 결과 수 설정 |
| `fetch_k` | MMR이나 Hybrid에서 먼저 가져올 후보 수 설정 |
| `lambda_mult` | MMR의 관련성과 다양성 비율 설정 |
| `weights` | Hybrid의 벡터 검색과 키워드 검색 비율 설정 |
| `context_k` | 답변 생성에 사용할 검색 문서 수 설정 |
| 프롬프트 경로 | 답변 생성에 사용할 프롬프트 파일 선택 |
| 생성 모델 | 답변 생성에 사용할 모델 선택 |
| 평가 모델 | 생성된 답변의 품질을 평가할 모델 선택 |
| 생성 평가 지표 | Faithfulness, Answer Relevancy, Answer Correctness 등 사용할 지표 선택 |

## output으로 나오면 좋은 것

### 사용한 input

- 실험 이름
- 사용한 문서와 평가 데이터
- 청킹 설정
- 임베딩 모델
- 검색 전략과 검색 설정
- 생성 모델과 프롬프트
- 평가 모델과 생성 평가 지표

### 실험 결과

- 검색 평가 지표 (예: Context Precision, Context Recall, Hit Rate, MRR 등)
- 생성 평가 지표 (예: Faithfulness, Answer Relevancy, Answer Correctness 등)
- 질문별 상세 결과 (검색된 문서, 생성된 답변, 개별 점수)
- trade-off 지표 (실행 시간, API 호출 비용/토큰 수 등)

### 저장 방식

- 실험마다 고유한 이름/타임스탬프로 결과 디렉터리 또는 파일을 구분하여 저장
- input(설정)과 output(결과)을 함께 저장해 실험 재현과 비교가 가능하도록 함
- 여러 실험 결과를 한 번에 비교할 수 있는 요약 테이블/파일 생성 (선택)

## 참고: CLI 인터페이스

`argparse`를 사용해 터미널에서 값을 전달할 수 있다.

```powershell
python app.py --document-path data.pdf --result-dir outputs --experiment-name chunk-test
```

옵션 이름에 하이픈(`-`)이 있으면 Python에서는 언더스코어(`_`)로 접근한다.
